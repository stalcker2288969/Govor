# Диагностика

Сначала установите commit/digest сервера, версию клиента и окружение. Эта документация описывает `a3401ce`; симптомы старой версии не следует автоматически переносить на новую. Локальные тесты и опубликованный production — разные среды.

## Запуск и доступность

| Симптом | Что проверить |
| --- | --- |
| SDK не найден | .NET SDK 10 и правила global.json |
| Нет configs/ban_usernames.json | ContentRoot, файл в publish/образе, регистр пути Linux |
| Ошибка обязательного секрета | Runtime-переменные нужного приложения, двойные подчёркивания, значение не пустое |
| Firebase ломает запуск | Enabled, service account JSON/путь и права; для разработки выключить |
| ping=200, ready=503 | Доступ к БД, TLS/CA, ожидающие миграции |
| Connection refused/502 | Порт приложения, состояние контейнера, reverse proxy и его журналы |
| После деплоя пропали файлы | Постоянный uploads, mount, права и прежняя структура путей |
| Browser CORS error | Точный origin включая схему/порт в Cors:AllowedOrigins |

[Запуск](getting-started.md), [конфигурация](configuration.md), [VPS](vps-deployment.md), [App Platform](timeweb-deployment.md).

## HTTP и команды

| Ответ | Действие |
| --- | --- |
| 400 | Проверить DTO, enum, длины, errorCode и контекст E2EE; refresh тоже может вернуть 400 |
| 401 | Проверить access/refresh, sid, срок/отзыв и серверное время; сериализовать refresh |
| 403 | Проверить участие/бан, автора, роль и владельца файла; смена токена не выдаёт права |
| 404 | Проверить тип ID: пользователь, чат, заявка и сообщение не взаимозаменяемы |
| 409 | Перечитать ревизию/поколение/состояние и повторить согласованную операцию |
| 413 | Учесть лимит хоста/прокси, multipart-overhead и размер ciphertext |
| 429 | Остановить частые повторы входа; за прокси проверить RemoteIpAddress |
| 500 | Сопоставить время, маршрут и журнал; не показывать внутреннее исключение пользователю |

Тело ошибки бывает ProblemDetails, строкой или пустым. У SignalR status находится внутри HubResult; успешное соединение не означает успешную команду. [Форматы](code-docs/hubresult-less-than-t-greater-than.md).

## Сообщения и шифрование

- Нет истории: проверьте chatId и recipientType, доступ, якорь и параметры пагинации.
- Файл загружен, но Send отклонён: проверьте uploader/OwnerType, MIME, пустой открытый encryptedKey и совпадение mediaIds в конверте.
- `E2EE_DEVICES_CHANGED`: перечитайте каталог и согласуйте получателей заново.
- Новое устройство не читает старое: проверьте восстановление архива и наличие прежних ключей; не генерируйте новый корень поверх старого архива автоматически.
- Ошибка времени конверта: E2EE проверяет отклонение CreatedAt до пяти минут; синхронизируйте часы.
- Повтор сообщения в UI: объединяйте HTTP, ответ Send и события по ID.

[Клиентский сценарий](client-integration.md), [E2EE](e2ee.md), [восстановление](password-recovery.md).

## SignalR и push

Проверьте правильный `/hubs/...`, актуальный access token, регистрацию обработчиков до StartAsync и поддержку WebSocket прокси. После reconnect перечитайте HTTP-состояние. При logout остановите автоматические повторы.

Для push проверьте Enabled, актуальный FCM-токен **текущей сессии**, разрешения ОС, Android channel `chat_messages`, APNs для iOS и журнал worker. Активный SignalR не подавляет push сам по себе; прочитавшие исключаются. Принятие FCM не гарантирует отображение. [Диагностика доставки](endpoints/push.md).

## Что известно о качестве

735 тестов SQLite прошли на проверенной ревизии; сборка выдаёт предупреждения, в том числе уязвимости ImageSharp 3.1.12. Текущий прогон не подтверждает production, PostgreSQL, реальные устройства и Firebase. [Проверки и ограничения](testing.md).

Старый отчёт от 03.10.2026 описывал дефекты исходной версии, многие из которых уже устранены. Его утверждения об отсутствии E2EE, сломанном HTTP presence, отсутствии проверки sid и неправильном SDK не являются текущими ограничениями.
