# Медиа и вложения

Требуются access token и роль User/Admin. Загрузка файла и отправка сообщения — отдельные операции.

## POST /api/media/upload

`multipart/form-data`:

| Поле | Назначение |
| --- | --- |
| `FromFile` | Непустой бинарный файл |
| `Type` | Число: Image=0, Video=1, Audio=2, File=3, Voice=4 |
| `MimeType` | Обязательная строка до 128 символов |
| `OwnerType` | Здесь разрешены только Message=0 и Avatar=1 |
| `EncryptedKey` | Для сообщения отсутствует или пустая строка; ключ расшифровки передавать нельзя |

Для `OwnerType=Message` клиент **сначала шифрует файл**. `MimeType` должен совпадать с `E2eeProtocol.EncryptedMimeType`; сервер сохраняет случайное имя `.bin` и тип File. Оригинальные имя, MIME и ключ содержатся внутри зашифрованного сообщения, не в открытых полях upload.

Лимит всего запроса и multipart — `20 000 000` байт; такой же предел проверяется для файла. Overhead формы и шифрования тоже занимает место: нельзя обещать загрузку исходного файла ровно 20 MB. Аватары не являются E2EE-вложениями; доступ к ним и профильный upload описаны отдельно.

Успех `200`:

```json
{"mediaId":"11111111-1111-1111-1111-111111111111","url":"<путь в хранилище>"}
```

`url` — внутренний путь, не публичная ссылка. Для сообщения используйте `mediaId` в списке вложений и метаданных зашифрованного конверта. Send проверяет загрузчика, тип владения, уникальность ID и соответствие вложений подписанному конверту. Чужой файл прикрепить нельзя.

## GET /api/media/download/{id}

Возвращает бинарный файл после проверки доступа. Для вложений учитывается участие в личном чате/группе и бан; непривязанная к сообщению загрузка не получает доступ к download только по признаку uploader. Отсутствие доступа или неизвестный ID могут дать `403`, поскольку доступ проверяется до чтения.

Ответ имеет `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`. Клиент расшифровывает содержимое и проверяет целостность перед отображением. Не используйте серверное имя/MIME зашифрованного файла как оригинальные пользовательские метаданные.

## Ограничения

Файлы буферизуются в памяти; запись в файловую систему и БД не образует единую транзакцию. Возможны неиспользованные файлы после сбоя/отмены отправки. Не удаляйте их по одному признаку возраста без проверки ссылок. [Хранение и резервные копии](../operations.md).
