# Обновление токенов

## POST /api/auth/token/refresh

Доступ анонимный. JSON:

```json
{"refreshToken":"<последний сохранённый refresh token>"}
```

Сервис ищет сессию по хешу строки, проверяет отзыв и срок, создаёт новую пару и условно заменяет хеш только если старый ещё актуален. `ExpiresAt` продлевается, `CreatedAt` сохраняет исходную дату открытия сессии.

Успех `200`:

```json
{"refreshToken":"<new refresh>","accessToken":"<new access>"}
```

| Случай | Ответ |
| --- | --- |
| Пустая строка | 400, `Auth.EmptyToken` |
| Неизвестный, истёкший или отозванный refresh | 400, `Auth.InvalidToken` |
| Сессия изменилась между чтением и условной заменой | 401, `Auth.InvalidToken` |

Повтор старого токена после успешной ротации не является штатным способом повторить запрос. Различие 400/401 зависит от момента обнаружения конфликта; не привязывайте восстановление клиента только к одному из статусов.

## Поведение клиента

Выполняйте один refresh за раз для всех параллельных HTTP-запросов и хабов. Сохраняйте оба новых токена вместе. Если ответ потерялся после серверного сохранения, старая строка уже может быть недействительна и потребуется новый вход.

Сетевой сбой или `5xx` не подтверждает недействительность токена. Повторный вход не должен удалять приватные ключи истории. [Пароль и восстановление](../../password-recovery.md).
