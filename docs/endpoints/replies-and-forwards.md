# Ответы и пересылки сообщений

Сообщения отправляются через ChatsHub.Send в /hubs/chats. Требуется access JWT и право отправки в чат. Для личного чата recipientId — PrivateChat.Id, recipientType — 0. Те же механизмы поддерживаются в группах и каналах с recipientType — 1 и соответствующей проверкой членства/роли.

## Ответ на сообщение

Вызовите `Send` в `/hubs/chats`, указав `replyToMessageId`:

```json
{
  "recipientId": "<chat-id>",
  "recipientType": 0,
  "encryptedContent": "<fresh E2EE envelope>",
  "replyToMessageId": "<original-message-id>",
  "mediaAttachments": []
}
```

`recipientType`: `0` — личный чат, `1` — группа/канал. Ответ должен ссылаться на существующее сообщение того же чата и типа. Сервер проверяет право отправки, включая блокировку в личном чате, бан в группе и роль администратора канала. Для E2EE `replyToMessageId` должен совпадать с `replyTo` подписанного конверта. В публичных группах допускается обычное содержимое согласно существующей политике.

Связь возвращается в результате `Send`, событиях сообщений и истории. Для превью ответа за пределами загруженной страницы используйте `GET /api/messages/{messageId}`. Ответ — `MessageResponse` с вложениями, реакциями и прочтениями. Отсутствующее сообщение и отсутствие доступа дают одинаковый `404`, без раскрытия чужого чата. После удаления оригинала ссылка остаётся; клиент показывает «Сообщение удалено». Содержимое удалённого сообщения сервер не архивирует в ответе.

## Пересылка

Используется тот же `Send`; добавьте `forwardedFromMessageId`, передайте новое содержимое и принадлежащие отправителю вложения для чата назначения:

```json
{
  "recipientId": "<destination-chat-id>",
  "recipientType": 0,
  "encryptedContent": "<new envelope encrypted for destination devices>",
  "forwardedFromMessageId": "<source-message-id>",
  "mediaAttachments": []
}
```

Сервер проверяет доступ отправителя к исходному сообщению и право отправки в чат назначения. Несуществующий или недоступный источник отклоняется без записи сообщения и push. Автор и дата источника берутся из БД, клиент не может передать их сам:

| Поле ответа/истории      | Значение                                     |
| ------------------------ | -------------------------------------------- |
| `senderId`               | Пользователь, выполнивший пересылку          |
| `forwardedFromMessageId` | ID непосредственно пересланного сообщения    |
| `forwardedFromUserId`    | Автор непосредственно пересланного сообщения |
| `forwardedFromSentAt`    | Дата отправки источника, UTC                 |

Это снимок происхождения без внешнего ключа: удаление источника не удаляет пересылку. При повторной пересылке указывается непосредственный источник, цепочка автоматически не разворачивается. Получатель не получает доступ к исходному чату.

Для зашифрованных сообщений клиент расшифровывает оригинал локально, затем шифрует новое сообщение для актуального набора устройств назначения с новым `messageId`. Вложения нужно заново загрузить от текущего пользователя; для E2EE зашифровать их новыми ключами, а ключи поместить внутрь конверта. Прямая подстановка чужих media ID не даёт прав на файлы. Сервер не расшифровывает содержимое и не может проверить, что текст пересылки идентичен оригиналу; метаданные происхождения не являются подписью исходного автора под новым содержимым.

Повтор одного E2EE-запроса с тем же ID идемпотентен; изменение источника, адресата, содержимого, ответа или вложений с прежним ID отклоняется. В публичных чатах без E2EE каждый `Send` создаёт новое сообщение. Для массовой пересылки выполняйте отдельный вызов для каждого сообщения и адресата.

## Установка

Для полей происхождения пересылки требуется версия API с миграцией MessagingAndUserBenefits. [Порядок обновления](../operations.md).
