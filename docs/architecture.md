# Архитектура и границы

MAUI → HTTP Controller / SignalR Hub → Application service → GovorDbContext → PostgreSQL. Бинарные файлы хранятся через IStorageService; транспорт событий и push вынесен в ChatNotificationService.

| Проект            | Ответственность                                                       |
| ----------------- | --------------------------------------------------------------------- |
| Govor.API         | Маршруты, хабы, активные access-сессии, DI, ошибки, DTO и уведомления |
| Govor.Application | Пользователи, группы/каналы, права, сообщения, реакции, медиа и push  |
| Govor.Contracts   | HTTP/SignalR запросы и ответы                                         |
| Govor.Domain      | Сущности, DbContext, EF-конфигурации и миграции                       |

Domain зависит от EF Core и содержит инфраструктуру БД. PrivateChat связывает двух пользователей; Message.RecipientId указывает на PrivateChat при RecipientType.User=0 либо ChatGroup при Group=1. Это ID чата, а не получателя-пользователя.

Роль сервера в JWT берётся из Invitation.IsAdmin. Роль группы вычисляется отдельно: ChatGroup.OwnerUserId — владелец, GroupAdmins — админы, активная GroupMembership — участники. GroupAccess объединяет права владельца/админа с незаблокированным членством; ChatAccess проверяет доступ к конкретному чату. Уникальные индексы запрещают дубли членства и административных ролей.

GroupManagementService сериализует изменения членства, ролей и ссылок на строке группы. Публикации, редактура, удаление, реакции и настройки канала используют тот же порядок блокировки. GroupAvatarService меняет аватар только для действующего владельца. Регистрация атомарно создаёт пользователя, расходует приглашение и добавляет членство в обязательном канале из ServerCommunitySettings; изменение этой настройки сериализуется с регистрацией.

Соединения ChatsHub автоматически входят в группы сессий. SignalR-события направляются активным сессиям действующих участников из БД; заблокированные участники исключаются. ConnectionStore и OnlineUserStore остаются в памяти одного процесса; для нескольких экземпляров нужна общая инфраструктура SignalR/presence.

Сообщение и задача push сохраняются атомарно; ChatPushWorker повторяет неудачные доставки. После успешного HTTP сохранения ChatNotificationService отправляет GroupProfileChanged и GroupMemberChanged через ChatsHub. Профиль перечитывается индивидуально через HTTP; статус/роль членства читаются после команды. При бане/выходе только событие собственного членства дополнительно доставляется пользователю, потерявшему доступ. Остальные события по-прежнему получают действующие участники. Отказ в правах/валидации не создаёт событий; сбой доставки не отменяет сохранение.

SignalR-события не имеют долговременной очереди. Клиент восстанавливает историю, прочтение, версии реакций, свои группы, открытый профиль и участников после reconnect через HTTP. Для реакций/политик и изменений сообществ push не отправляется. При параллельных командах порядок событий не гарантирован, поэтому актуальные права берутся из HTTP состояния, а не из последнего полученного уведомления.

[Группы и каналы](groups.md), [реакции](endpoints/reactions.md), [прочтение](endpoints/message-read.md) описывают текущую рабочую версию. E2EE сообщений и архивов реализовано; [модель доверия](e2ee.md) и [восстановление по паролю](password-recovery.md) описаны отдельно. Для E2EE повтор той же отправки распознаётся по подписанному messageId и контексту. Согласованное присутствие между инстансами и общий ключ идемпотентности всех команд не реализованы.
