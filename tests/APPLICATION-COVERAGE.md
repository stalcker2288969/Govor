## Что проверяется

Unit-тесты проверяют JWT, пароли, username, claims, присутствие, файловое
хранилище, push dispatch и ошибки транспорта, границы форматов E2EE. Mocks
используются для внешних зависимостей и управляемых отказов.

Интеграционные тесты проверяют регистрацию и роли, профили, дружбу и блокировки,
сессии и refresh/replay, криптографические ключи, push-токены, сообщения и
прочтения, доступ к медиа, группы и аватары, реакции и наборы реакций.
Проверяются права доступа, отсутствующие данные, валидация, ошибки сохранения
и откат транзакций. Перехватчик команд БД воспроизводит отдельные отказы и гонки.

Серверные тесты дополняют проверку через HTTP и SignalR: авторизация, E2EE,
некорректные конверты и маршрутизация, лимиты устройств, вложения, Firebase
batching и классификация ошибок. Внешний Firebase transport подменён.

SQLite использует отдельную in-memory БД. PostgreSQL проверяет реальные
миграции, ограничения и поведение запросов: каждый экземпляр тестовой БД
получает уникальную схему, которая удаляется после теста. Для локального
прогона использован отдельный временный кластер на 127.0.0.1:55439 с БД
govor_validation_tests. Он не использует рабочие базы.

## Реализованные методы и исправления

- Last seen читается из БД; для неизвестного пользователя возвращается null.
- Медиа по URL ищется по точному URL в метаданных и читается из storage;
  пустой URL и отсутствующие данные обрабатываются явно.
- Блокировка сохраняет инициатора как владельца блокировки. Другой участник
  не может перехватить или снять её. Разблокировка переводит отношение в
  Rejected: для дружбы снова требуется согласие.
- Новые криптографические сессии и одноразовые ключи явно добавляются в EF,
  исправляя ошибочное UPDATE и DbUpdateConcurrencyException.
- Ротация и расходование ключей проверяют владельца сессии; чтение ключей
  включает SignedPreKey.
- Чтение и удаление файлов проверяют канонический путь с границей корневой
  директории, включая обход через `..` и похожее имя соседней папки.
- Пустой username возвращает ошибку валидации вместо NullReferenceException.

## Подсчёт и воспроизведение

Из корня репозитория после Release-сборки:

```powershell
dotnet test Govor.Server.slnx -c Release --no-build --no-restore --logger trx --results-directory artifacts/coverage --collect 'XPlat Code Coverage;Format=json,cobertura'
./tests/Measure-ApplicationCoverage.ps1 -ResultsDirectory artifacts/coverage
```

Для PostgreSQL задайте TEST_POSTGRES_CONNECTION согласно [README.md](README.md).
Запуски с покрытием и другие тестовые запуски не должны одновременно использовать
одни и те же выходные сборки. Для нового измерения используйте свежую папку результатов.

Скрипт объединяет попадания по строкам и ветвям Govor.Application.dll из всех
четырёх проектов, устраняет дубликаты и создаёт application-coverage.json.
Итог: 2727 из 2758 строк, 1199 из 1282 путей ветвления. Код сборки Application
не исключался из измерения. CI на SQLite и PostgreSQL требует минимум
98% строк и 92% ветвей; снижение ниже порога завершает проверку ошибкой.

Локальный итоговый отчёт:
`artifacts/test-results/api-final-sqlite/application-coverage.json`.
TRX итоговых прогонов находятся в `api-final-sqlite` и
`api-final-postgres` под `artifacts/test-results`.

## Оставшиеся ограничения

Покрытие не равно 100%: остаются 31 строка и 83 пути ветвления. Это в том числе
старые конструкторы исключений/результатов, отдельные защитные проверки E2EE,
ветви ошибок файловой системы и media processor, обработка отдельных гонок
и отказов в authentication, groups, reactions и push. Точные строки перечислены
в JSON-отчёте; показатель строк не означает полного покрытия всех условий.

Эти результаты подтверждают прохождение проверенных сценариев, но не доказывают
отсутствие всех ошибок. Нагрузочные испытания, production-развёртывание и
доставка push на физические устройства в эту проверку не входили.
